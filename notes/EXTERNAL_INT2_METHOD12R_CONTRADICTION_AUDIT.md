# External Int2 Method.12R — mixed-boundary contradiction audit

Дата: 2026-07-28. Ветка `feature/external-int2-hyperint-integration`.
Артефакт: `validation/external_int2_method12r.json`; скрипт
`scripts/audit_external_int2_method12r.py`; тесты
`tests/test_external_int2_method12r.py`.

## Вердикт

**FOUR_TERM_RELATION_INVALID.** Сертифицированное четырёхчленное соотношение
`J[Target] == C1*J[L1] + C2*J[L2] + C3*J[L3] + C4*J[L4]` **не является верным
интегральным тождеством**. Три независимых свидетельства:

1. **Laurent-порядок (точно, symbolic).** `[ep^-3]` правой части равен
   `-1/(6*r^2)` и не зависит ни от одной конечной части мастеров; у цели
   `JTarget = -2/(3*r*ep^2) + O(1/ep)` полюса `ep^-3` нет.
2. **Численная проверка в камере сходимости** `ep=-3/5, r=1`, где сходятся все
   пять интегралов: относительная невязка **~1.07** (два независимых маршрута
   квадратуры), в 10^4 раз выше любой оценки погрешности.
3. **LF-гейт**: мастер `L4 = [0,0,1,-1,0,0,-1]` **не локально конечен** —
   `base_score == 0` на совместном луче бесконечности `(0,-1,-1)`.

Method.11c переклассифицирован: **formal row-span only**. `Status=Success` и
`AllLocallyFinite=True` в экспортированных артефактах **отозваны**.

## Точный смешанный луч

`d = (0,-1,-1)` — это `x5 -> Infinity`, `x7 -> Infinity` при фиксированном
`x2` (соглашение пакета: `x_i ~ lambda^(d_i)`, `lambda -> 0`, поэтому
отрицательная компонента = уход на бесконечность).

| метка | score(d) | при ep=0 | в камере ep=-3/5 | LF (до) | LF (после) |
|---|---|---|---|---|---|
| Target | `-ep` | 0 | 3/5 | False | False |
| L1 | `1-ep` | 1 | 8/5 | True | True |
| L2 | `2-ep` | 2 | 13/5 | True | True |
| L3 | `1-ep` | 1 | 8/5 | True | True |
| **L4** | `-ep` | **0** | 3/5 | **True** | **False** |

`score = 0` при `ep=0` — ровно логарифмическая расходимость, измеренная в
Method.12N (`J_4(ep) = -1/(r*ep) + O(1)`, лог-наклон против предсказания `1/r`
совпал до ~1e-6 в трёх кинематических точках). При `ep=-3/5` тот же луч даёт
`3/5 > 0` — поэтому в камере интеграл сходится и численная проверка фазы D
корректно поставлена.

## Первый конкретный дефект реализации

**`compute_candidate_rays` (`src/parametric_ibp_lf_reducer/valuations.py`) выдавал
неполный набор лучей.** Для этого семейства он давал 12 лучей (координатные
`±e_i`, ньютоновские мономы каждого `G_l` и «occurring»-диагонали); полный
полиэдральный набор — 18, и `(0,-1,-1)` в старом наборе **отсутствовал**.

Сопутствующие обстоятельства (важны для оценки, почему баг дожил до
сертификата):

- Случайная «страховочная сетка» (`_random_directions`, 64 направления,
  seed 20260706, координаты в `[-3,3]`) — лотерея, а не доказательство: для
  `(0,-1,-1)` (и его кратных) вероятность промаха ~57%, и она промахнулась.
- `vector_field_surface_free` брала тот же неполный набор лучей, то есть
  фильтр tangent-строк наследовал ровно тот же пробел.
- `coordinate_primitive_surface_free` **по построению** компонент-локальна: она
  проверяет только показатель на границах `x_i -> 0` и `x_i -> Infinity` и
  никогда — сходимость поперечного `(N-1)`-мерного поверхностного интеграла.
  Поверхностный член вида `0 * Infinity` она пропускает. Это независимый
  дефект того же класса, и по счётчикам фазы C он **крупнее**: под
  исправленный фасетный критерий не подпадает 21% production-строк
  (limit-политика) и 43% chamber-only строк.

## Исправление (что изменено в `src/`)

Добавлены `newton_wall_normals` и `complete_polyhedral_rays`:

- «стены» = гиперплоскости `(a - a') . d = 0` по парам мономов **одного**
  `G_l`; это в точности стены общего измельчения нормальных вееров, поскольку
  `base_score` линеен всюду, кроме переключения минимума в `val_d(G_l)`;
- лучи = примитивные целочисленные образующие пересечений любых `N-1`
  независимых стен (плюс координатные оси). Каждый экстремальный луч полного
  веера в `R^N` лежит минимум на `N-1` независимых стенах, поэтому это
  **надмножество** экстремальных лучей; положительность score на надмножестве
  только консервативнее;
- при выходе за бюджет перечисления (`RAY_ENUMERATION_BUDGET`) флаг
  `complete=False`, и `is_locally_finite` возвращает `"Unknown"`, а не `True`.

Область изменения — **только LF-гейт** (`is_locally_finite`,
`explain_local_finiteness`). Фильтры генерации строк (`surface.py`) намеренно
оставлены на прежнем (эвристическом) наборе лучей: по условию аудита
production-строки не добавляются и не удаляются до разбора фазы C; в коде это
зафиксировано явным комментарием и вызовом `heuristic_candidate_rays`.

Проверка неспецифичности: в семействе D4 (4 переменные, другой набор
полиномов) метка `(1,1,1,0,-1,0,-1)` тоже маргинальна на луче `(-1,0,-1,0)`
(score 0), которого нет в эвристическом наборе. При этом **все** мастера
валидационных кейсов (D4 M1–M5, example4_star, external_int1) остаются
LF-True — исправление не ломает ни один валидированный ответ.

## Фаза D — прямая численная проверка тождества

Точка: `ep = -3/5`, `r = 1`. Точные коэффициенты:
`C1 = 1/12`, `C2 = -16/9`, `C3 = 50/27`, `C4 = 44/27`.

Маршрут A — 3-D градуированная тензорная сетка Гаусса–Лежандра (float64,
`x = u/(1-u)` с точным якобианом, диадическое сгущение к обоим концам,
лестница (12,6) → (24,12)).
Маршрут B — **точное преинтегрирование по `x7`** и 2-D сетка в mpmath
(dps 30): `Int[(1+x7)^(-1-ep) (A+B x7)^(ep-1)] = (B^ep - A^ep)/(ep (B-A))`
(`A = 1+r x2 x5`, `B = 1+x2`), случаи `G3^(ep-2)` и `x7*G3^(ep-2)` получены
дифференцированием по `A` и подстановкой `x7 = ((A+B x7) - A)/B`; все три
замкнутые формы численно сверены с адаптивной квадратурой перед использованием.

| | Target | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| маршрут A | 3.9267 | 2.1420 | 1.0374 | 0.30532 | 0.49787 |

`RHS = C1*L1 + C2*L2 + C3*L3 + C4*L4 = -0.2891` против `Target = 3.9267`:

- абсолютная невязка **4.216**, относительная **1.074**;
- все четыре мастера положительны, `C2 < 0` — никакая ошибка в одном интеграле
  не спасает тождество: чтобы сойтись, потребовалось бы `J2 ≈ -1.33`.

Точные числа, лестницы, оценки погрешности и согласие маршрутов — в
`validation/external_int2_method12r.json` (`phase_d_numeric_identity`).

## Фаза C — ревалидация строк

Воспроизведение записанного диффа Method.10 — **точное**:

| | limit | chamber | chamber-only | limit-only |
|---|---|---|---|---|
| 12R | 46737 | 49439 | 2702 (coord 1024 + tangent 1678) | 0 |
| записано в Method.10 | 46737 | 49439 | 2702 (1024 + 1678) | 0 |

Ревалидация против исправленных критериев (строка объявляется невалидной,
только если падают **все** её принятые обоснования):

| набор | ещё валидны | отвергнуты | coordinate | tangent |
|---|---|---|---|---|
| chamber-only (2702) | 1532 | **1170 (43%)** | 567 / 457 | 965 / 713 |
| production limit (46737) | 36872 | **9865 (21%)** | — | — |

То есть дефект **не локализован в chamber-расширении**: пятая часть
production-строк (limit-политика) не имеет корректного обоснования.
Типичный отвергнутый пример: метка `[-1,0,0,-3,0,-3,0]`, `var = x5`,
`P = x5^2` — компонент-локальный тест проходит, но на луче `(1,-1,0)`
(`x2 -> 0`, `x5 -> Infinity`) фасетный score равен `-1`: поверхностный член
там расходится.

Пере-скрининг записанных Method.7 dual-witness'ов по выжившим строкам:
`1685 -> 1362` breaks на всех шести (sample, prime) — то есть обоснование
Method.10 rerun'а сокращается, но не исчезает полностью (честный
промежуточный результат, а не коллапс).

Быстрый целочисленный фильтр потока (`FastFluxFilter`), которым сделан свип
Level-0, сверен с библиотечным `vector_field_surface_free` на 4 × 240
случайных парах (label, field) — 0 расхождений.

Что именно проверялось:

- воспроизведение диффа Method.10 (limit-политика vs chamber-политика
  `ep=-3/5`, дедуп по `dedup_key`);
- каждая chamber-only строка — по **всем** её принятым обоснованиям (строка
  объявляется невалидной, только если падают все её обоснования) против
  (i) полного набора лучей для tangent-потока и (ii) исправленного фасетного
  критерия для координатных IBP:

  > поверхностный член на фасете `x_i` исчезает, только если
  > `score(d) - d_i > 0` для **каждого** луча `d` полного набора с `d_i != 0`;
  > на чистых координатных лучах это в точности сегодняшний тест
  > (`exp_zero > 0`, `exp_inf < 0`), новое содержание — смешанные лучи;

- пере-скрининг записанных Method.7 dual-witness'ов по выжившим строкам
  (только скалярные произведения, без RREF).

Аудит **не** добавляет и не удаляет production-строки: это счётчики того, что
дало бы исправление.

## Что отозвано и что устояло

Отозвано:

- `validation/external_int2_lf_result.m`: `Status -> "Revoked(Method.12R)"`,
  `AllLocallyFinite -> False`, `NonLFTerms -> {{0,0,1,-1,0,0,-1}}`,
  `IndependentValidationPassed -> False`, блок `Method12RInvalidation`;
- `validation/external_int2_lf_full_formula.m`: баннер REVOKED + блок
  `Method12RRefutation` (коэффициенты и интегранды сохранены дословно);
- `validation/external_int2_lf_certificate.json`: добавлен ключ `downgrade`
  (`formal_row_span_only`, `refuted_by: Method.12R`); сами проверки, ранги,
  точки и коэффициенты не тронуты;
- `scripts/export_external_int2_lf_masters.py` теперь корректно падает на
  Gate 3 (`master (0,0,1,-1,0,0,-1) failed the LF check: False`) — это
  ожидаемое поведение, артефакты повторной генерацией не «чинить».

Устояло:

- модульные row-span проверки Method.11 Phase C (4 точки × 2 простых,
  InSpan 8/8, ранг 26984) — они и не утверждали аналитическое значение;
- Method.12N (артефакт заморожен, оракул не читался) — его отрицательный
  результат теперь объяснён структурно;
- Method.2 leading-pole audit (`-4/(s*t^2*ep^4)` для полного объекта) — он
  получен независимо от редукции.

## Следующие шаги (требуют одобрения; НЕ выполнялись)

1. Распространить исправленный набор лучей на `vector_field_surface_free` и
   ввести фасетный критерий в `coordinate_primitive_surface_free` — это удалит
   часть production-строк и потребует пере-прогона всей цепочки Method.10/11
   (см. счётчики фазы C).
2. Новый поиск LF-базиса **запрещён** до разбора этого аудита: базис должен
   строиться против полного набора лучей, иначе повторится тот же класс ошибки.
3. Кандидат на замену 4-го элемента базиса: комбинация без маргинальной грани
   (score > 0 на `(0,-1,-1)`), либо явная схема вычитания полюса.
